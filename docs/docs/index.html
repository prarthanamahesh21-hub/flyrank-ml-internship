Abstract

Content teams need a practical way to decide which pages should be reviewed first for a possible content refresh. This study evaluates whether page-level content age, word count, Google Search Console performance, and Google Analytics 4 engagement signals can support that prioritization task. Using the FlyRank ML Internship dataset and a March 2026 feature window, I defined a page-level review-priority target, checked the available signals for leakage, and compared Logistic Regression against a Week-4 rule-based baseline using the same held-out validation split. The Logistic Regression model achieved an observed ROC-AUC of 0.8992 compared with 0.5308 for the baseline, while a stricter client-grouped validation produced 0.8814 ROC-AUC on unseen clients. These results suggest that the measured signals can provide useful decision support for ranking pages for review, while the model should not be interpreted as evidence that refreshing a page will itself cause improved search or engagement performance.

1. Introduction / Problem Statement

Content teams often have more pages available for review than they can realistically investigate at the same time. When deciding which pages deserve attention first, a simple and reproducible prioritization approach can help turn multiple page-level signals into an ordered review queue.

Research question:
Can page-level content, search, and engagement signals be used to prioritize content pages for possible refresh review?

The goal is not to determine whether a page should definitely be refreshed, nor to claim that refreshing a page will cause better performance. Instead, the goal is to build a decision-support ranking that helps identify pages that may warrant earlier human review.

The experiment combines content characteristics with observed search and engagement signals and compares a learned model with a transparent rule-based baseline.

2. Data

Dataset and development window

This analysis was built on the FlyRank ML Internship dataset. The working dataset contains approximately 30,000 content pages across multiple clients and includes content metadata and performance-related signals.

The feature and decision window is March 2026, covering March 1 through March 31, 2026. The subsequent outcome window covers April 1 through April 30, 2026.

Target

A page receives label 1 when its Google Search Console clicks during the April 2026 outcome window are greater than zero. It receives label 0 when those clicks are zero.

After feature construction, filtering, and modeling joins, the final model frame contained 293,504 rows.

Public-safe handling

No client names, private search queries, credentials, or private business information are included in this research artifact. The paper reports aggregate methodology and measured results rather than client-level information.

3. Methodology

Task framing

The task is framed as a binary page-level prioritization problem. The model produces a score that can be used to order pages for human review rather than automatically approve a content refresh.

Baseline

A transparent rule-based baseline was established during Week 4 before model development. The baseline provides a simple reference point for determining whether the learned model provides stronger separation than the earlier rule-based approach.

Model

The final model is a Logistic Regression classifier using the five retained page-level features. Logistic Regression was selected as a relatively simple and interpretable first model whose output can be used for ranking.

Validation

The original model and baseline were evaluated on the same held-out test pages using ROC-AUC. A separate client-grouped validation was then performed to test whether performance remained strong when clients in the test set were not represented in training.

Leakage checks

  • The target label was not included among the model features.
  • Future-outcome information was excluded from the final feature matrix.
  • Feature/target overlap was checked.
  • The final feature list contains only the five documented predictors.
  • Duplicate content IDs were checked during validation.

5. Limitations & Honest Framing

Observational data

The analysis uses historical observational signals. The relationships learned by the model should not be interpreted as causal relationships. The results do not demonstrate that changing or refreshing a page will cause higher search visibility, clicks, or engagement.

Target definition

The model predicts the specific binary outcome defined for this project: whether a page recorded more than zero Google Search Console clicks during the April 2026 outcome window. This is a proxy for the prioritization objective and does not capture every factor a content team might consider.

Validation scope

The reported scores were measured within the defined dataset and validation designs. They should not be assumed to represent performance on every website, industry, client, or future time period.

Feature limitations

The model does not fully represent factors such as search intent, content quality, topic difficulty, seasonality, business importance, recent editorial changes, or competitive conditions.

Metric limitations

ROC-AUC measures ranking and separation performance. It does not directly measure successful refreshes, traffic growth, conversions, reviewer agreement, or return on investment.

Honest conclusion

Within this dataset and validation setup, the selected page-level signals provided substantially better predictive separation with Logistic Regression than the Week-4 rule-based baseline. The model is best treated as a decision-support ranking for further human review.

6. Ranked Recommendations / Action Playbook

  1. Review the highest-ranked pages first. Use the model score to order pages and begin human investigation with the highest priority group.
  2. Check search visibility and clicks together. Investigate pages with meaningful search visibility but relatively weak click response.
  3. Use content age as review context. Older high-ranked pages can receive additional freshness review, but age alone does not establish that content is outdated.
  4. Consider traffic and content characteristics together. Review pageviews and word count alongside search performance and content age.
  5. Keep a human review step before any refresh. A high model score identifies a page for investigation; it does not automatically justify changing the page.

Recommended workflow

1. Score pages
2. Rank by model score
3. Review highest-priority pages
4. Diagnose search and engagement signals
5. Check content freshness and quality
6. Decide whether a refresh is justified
7. Measure the outcome separately
Operating principle: Use the model to decide what to look at first, not what to change without review.
